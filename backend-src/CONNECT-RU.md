# TRED 0.3.20 — компактный анализ и потоковые ответы LunaRoute

Приложение получает данные открытого Pocket Option через расширение на твоём компьютере. Баланс демо- и реального счёта и общий кабинет на устройствах уже проверены владельцем. Пароль, cookies и брокерская сессия остаются у тебя. В этой версии нет команд открытия ордеров.

## Обновить работающий TRED

Исправление ожидания LunaRoute находится в серверном коде, поэтому здесь **нужен один перезапуск сервера**. Сохранённый ключ, выбранная модель, база и подтверждённые профили сохраняются. Повторно запускать настройку ключа не нужно. Быстрый способ обновления только расширения из 0.3.19 не загружает новый клиент ИИ.


1. Скачай [архив 0.3.20](https://kofemolka787.github.io/Tred/tred-backend-v0.3.20.zip). Правой кнопкой по ZIP → «Извлечь всё». Используй всю новую папку `TredBackend` либо скопируй её содержимое с заменой файлов в прежнюю папку TRED. Важна вся папка, включая `SHA256SUMS.json`.
2. В старом окне сервера нажми **Ctrl+C**. Запусти `START-WINDOWS.cmd` из обновлённой папки. Существующая база и ключ связи сохраняются в `%LOCALAPPDATA%\TRED\data`; удалять эту папку не нужно.
3. Расширение осталось **0.3.12**: если эта версия уже установлена, переустанавливать или удалять его не нужно. Более старую версию обнови файлами из `connector` и круглой стрелкой у той же карточки TRED.
4. Обязательно обнови вкладку Pocket Option один раз, чтобы новый обработчик увидел каталог и историю в новом канале. Переключать пары вручную для сканирования не требуется.
5. Новый запуск сервера может выдать другой `https://…trycloudflare.com`. Если адрес поменялся, один раз сохрани его в TRED → «Кабинет → Связь и код подключения» и в расширении через «Изменить подключение». При запросе расширением нового кода используй свежий код текущего сервера. Само обновление файлов не отзывает прежний ключ. Адрес приложения на других устройствах подтянется через Telegram.
6. В Telegram открой меню приложения ⋯ → «Перезагрузить».
7. Если LunaRoute уже настроен, этот шаг пропусти. Иначе запусти **`SETUP-LUNAROUTE.cmd`** из новой папки `TredBackend`. Вставь ключ **LunaRoute `lr_…`** локально: символы видны. Настройщик получает реальный каталог доступных моделей; Enter выбирает показанную модель, либо введи номер другой модели. Затем выполняется короткий тестовый запрос со структурированным JSON: он расходует немного кредитов LunaRoute. Только после проверенного ответа сохраняются провайдер, модель и ключ. Настроенный сервер читает их без дополнительного перезапуска. Открой TRED заново: в статусе ИИ должны быть **LunaRoute** и выбранная модель.

Не запускай два сервера одновременно. Не выбирай «Отключить связь» для обновления — эта кнопка отзывает ключ и очищает текущие снимки счёта.

## Переключение на LunaRoute

Серверный адаптер LunaRoute появился в 0.3.18. Если он уже проверен и ключ сохранён, повторять настройку в 0.3.20 не нужно. Для перехода с 0.3.16/0.3.17 сначала обнови **весь архив и перезапусти сервер**, затем запусти `SETUP-LUNAROUTE.cmd`. Только запуск настройщика при старом сервере недостаточен. База, привязка кабинета, настройки профилей и балансы остаются в той же личной папке `%LOCALAPPDATA%\TRED\data`.

Отдельная оплата OpenAI API для режима LunaRoute не требуется: используются кредиты твоего аккаунта LunaRoute. Это не означает бесплатные или неограниченные запросы. Наличие ключа само по себе не гарантирует кредитов; короткая проверка выполняет реальный запрос модели. Если модель не поддерживает требуемый Responses API/JSON, настройка не сохраняет непроверенное подключение: выбери другую доступную модель.

Ошибки называют фактического провайдера: LunaRoute HTTP401 — ключ отклонён, HTTP402 — не хватает кредитов, HTTP403 — доступ запрещён, HTTP404 — модель/маршрут недоступны, HTTP429 — ограничение запросов/квоты. У прямого OpenAI распознаются отдельные коды `insufficient_quota` и `rate_limit_exceeded`. Текст ответа провайдера и ключ в диагностику не выводятся. При отказе прежние сохранённые настройки сохраняются. Прямой OpenAI остаётся отдельным вариантом через `SETUP-AI.cmd`; скрытого переключения провайдера при ошибке нет.

## Что изменилось после ожидания LunaRoute

Подробные свечи и признаки передаются только по парам с полными свежими данными. Остальные строки каталога остаются в запросе как явные сводки отсутствующих данных; их графики не объявляются проанализированными. В тесте с 39 парами и одной готовой парой размер снимка уменьшился с 329798 до 27148 байт. Все 39 строк сохранились, и потребовался один вызов модели. Это измерение тестовых данных, не обещание времени ответа сервиса.

Пакеты LunaRoute ограничены размером 48000 байт и 64 строками; при большом количестве полных графиков используется несколько пакетов и сравнение выбранных моделью сценариев. Итог для единственного победителя не запрашивается повторно. Вход по-прежнему проверяется по реальным закрытым свечам, текущей цене и сроку действия: ускорение не отключает эти проверки.

LunaRoute вызывается с потоковым ответом Responses API. Клиент читает события по мере поступления и принимает только `response.completed` с проверяемым структурированным решением. Он не ждёт закрытия HTTP-соединения после готового результата. Промежуточные тексты, рассуждения, оборванные и незавершённые ответы не становятся сигналом. JSON-ответы также поддерживаются.

Ошибки ожидания ответа, DNS, TLS и разрыва соединения различаются. Тайм-аут сам по себе не доказывает проблему с интернетом или ключом. Повтор того же платного запроса после тайм-аута автоматически не отправляется. Новые пакеты не отправляются после истечения общего бюджета анализа; незапущенные запросы при ошибке отменяются. Сетевое чтение имеет тайм-аут 35 секунд без данных, бюджет анализа проверяется на границах чтения и перед отправкой.

`python check_ai_stream_http.py` проверяет настоящий локальный HTTP/1.1 с chunked SSE, задержками, открытым соединением после готового ответа и обрывом после правдоподобного частичного JSON. `python -m unittest -q test_ai_response test_ai_market` проверяет классификацию ошибок, ограничения потока, отсутствие автоматических повторов и сохранение всех 39 строк каталога. Это фикстуры; реальная скорость модели на аккаунте владельца проверяется после обновления.

## Получить ИИ-сценарий на 5, 10 или 15 минут

1. Оставь компьютер, сервер и торговый терминал Pocket Option открытыми. В TRED выбери OTC либо обычный рынок и длительность 5/10/15 минут. Закрытие обычных пар не включает OTC без твоего выбора.
2. «Каталог» и выбор пары содержат все инструменты, которые передал терминал, без ограничения первыми 10/24/100 строками; поддерживаются также категории помимо валют. Это каталог текущего брокерского канала, не независимая гарантия полного списка у провайдера.
3. В анализ идут открытые инструменты выбранного рынка с явно поддерживаемой экспирацией и выплатой не ниже установленного минимума (по умолчанию 85%; приоритет 92%). Закрытые/низкодоходные инструменты остаются видны с причиной исключения. Выплата не равна вероятности выигрыша.
4. Расширение само запрашивает поток цен (`subfor`) и историю (`loadHistoryPeriod`) через уже открытый брокерский WebSocket. Авторизация и ключи брокера не копируются. Нет команд открытия сделки или смены активного графика. Лимит — один запрос в 400 мс и до двух неотвеченных запросов истории; попытки распределяются по каталогу, а не застревают на первой проблемной паре.
5. Нажми «Получить сигнал» один раз. Приложение показывает загрузку и число пар с полными данными. Оно ждёт доступные пары в пределах установленного времени, затем передаёт фактическую историю и признаки модели через LunaRoute. Если брокер не ответил по части инструментов, это видно в охвате и в данных модели; анализ всех строк не означает наличие свечей для каждой. Модель может отклонить все входы.
6. ИИ принимает окончательное решение по переданным стратегиям и объясняет его. При большом каталоге снимки LunaRoute делятся по размеру до 48000 байт данных и 64 строк; для прямого OpenAI остаются порции до 16 пар. Затем сравниваются выбранные моделью сценарии, чтобы не потерять инструменты из-за контекста. Это может увеличить число платных API-запросов и задержку; фиксированное время ответа не гарантируется.
7. При сигнале показаны пара, вверх/вниз, длительность, предполагаемое время завершения при входе сейчас, зона входа и срок её действия (30 секунд). Проверь выбранную пару и время закрытия на стороне брокера. Кнопка «Я открыл сделку» только отмечает твой самостоятельный вход.

На каждый из двух совместимых периодов нужны 80 закрытых последовательных свечей. Предпочтительные периоды M1+M5 для 5/10 минут и M5+M15 для 15 минут; возможны M2+M10 и полное агрегирование младших свечей. Период свечи и длительность сделки различаются. Открытые/будущие/пропущенные интервалы не дорисовываются. После ответа ИИ сервер повторяет проверку цены, выплаты, доступности, зоны и актуальности использованных закрытых свечей. Изменившийся вход пропускается.

### Настройка и хранение ключа ИИ

`SETUP-LUNAROUTE.cmd` / `python configure_ai.py --provider lunaroute` сохраняет ключ, модель и провайдера в личном `ai-settings.json` рядом с базой, на Windows — `%LOCALAPPDATA%\TRED\data`. Он отсутствует в ZIP, расширении, API-состоянии, Telegram CloudStorage и публичных исходниках. Платный доступ закрепляется за текущим связанным Telegram-кабинетом; другие пользователи сервера его не получают. Если в базе несколько кабинетов, настройщик попросит выбрать свой ID. Для разработки: `LUNAROUTE_API_KEY`, `LUNAROUTE_MODEL`, `TRED_AI_PROVIDER=lunaroute` и список владельцев `TRED_AI_ALLOWED_USERS`. Прежний `OPENAI_API_KEY` не подменяет сохранённый ключ LunaRoute. Модели с ID вида `provider/model` поддерживаются. CLI/Node.js не нужны.

Модель получает обезличенные рыночные OHLC, котировки, периоды, выплату и проверяемые признаки структуры/SMC. Баланс, логин, пароль, Pocket ID, Telegram ID и ключ связи в запрос не входят. Отправляется `store:false`. Транспорт — HTTPS к официальному `gw.lunaroute.com/v1/responses`, Bearer-ключ `lr_`; TLS не отключается. Endpoint задан в коде, а не произвольной строкой в настройках. Прямой OpenAI использует отдельный `api.openai.com/v1/responses`; ключ LunaRoute туда не отправляется. При отказе провайдера нет скрытого перехода на другого провайдера или сигнал без ИИ. Если настройки сменились во время анализа, прежний ответ отбрасывается. В карточке указаны фактический провайдер и модель. Успешная локальная проверка не гарантирует доступность сервиса при будущих запросах.

### Что именно анализируется

Подтверждённые двумя последующими свечами swing-экстремумы; HH/HL либо LH/LL; BOS с импульсом; последняя противоположная свеча перед импульсом как предполагаемый order block; реакция на FVG; вынос локального экстремума с возвратом; направленный канал по подтверждённым экстремумам. Вход требует реакции на зону и согласованного направления старшего таймфрейма. Открытые и будущие свечи не участвуют. Цена не должна уйти далеко от зоны.

Локальные правила рассчитывают подтверждённые признаки и допускают только сценарии с реакцией на зону и согласованием периодов. Модель через выбранного провайдера сравнивает полученные пары, выбирает один из допустимых сценариев либо отвергает их все; это отдельный реальный вызов модели, а не переименование правил в ИИ. В контексте — признаки по всем подходящим парам и последние 32 OHLC на каждом периоде. Ссылки ИИ на период/время проверяются, направление и символ не могут выйти за фактически подтверждённые сценарии. ИИ не видит брокерский стакан или всю биржевую ликвидность. Проходимость стратегии не измерена, прибыль и вход на каждое нажатие не гарантируются.

Расширение получает обычную/Fast-историю, сопоставляет отсутствующий период по индексу запроса, сохраняет до 1600 свечей на период и передаёт их пакетами до 250 событий. Поддерживаемые ответы истории с реальными тиками также дают котировки с исходным временем. Закрытие OHLC не подставляется вместо живой цены. Автозагрузка начинается при работе расширения и связанного сервера, даже при закрытом окне расширения. Браузер может замедлять фоновые таймеры; отзыв связи и закрытие терминала прекращают работу.

### Что исправлено после «свежих котировок 0»

Первая отправка `subfor` больше не считается вечным подтверждением подписки: при отсутствии свежих тиков попытка повторяется. Дополнительно запрашивается короткое окно реальных тиков через `loadHistoryPeriod` с `period=1`, `offset=20` и текущим временем в явно выбранном профиле UTC/UTC+2. Это отдельный запрос цен; свечи периода 1 не поступают в стратегию. При получении свежих котировок лишние запросы прекращаются. Общие ограничения темпа и двух неотвеченных запросов сохраняются.

Из ответа принимается только фактически переданная цена с её исходным временем. Закрытие OHLC не становится текущей котировкой. Время не сдвигается к моменту получения; прежние проверки свежести сохраняются. В очереди отправляется последняя полученная котировка каждой пары, а не весь старый поток. При ограничении очереди новые цены сохраняются; баланс и состояния канала имеют приоритет. Добавлена обработка однозначных массивов тиков без оболочки события и управляющих пакетов между заголовком и бинарным вложением.

`python check_quote_recovery.py` проверяет 33 истории без котировок, восстановление цен, модельный анализ всех 33 строк, исходное время, сохранность баланса и отсутствие торговых команд. `--legacy-server /path/to/0318/TredBackend` проверяет совместимость с прежним сервером. Брокер и модель в проверке — локальные фикстуры; это не сертификация нативного протокола Pocket Option.

### Что исправлено после «свечей 0 / 0»

Добавлена обработка `loadHistoryPeriodFast` / `updateHistoryNewFast`, истории тиков и свечей M2/M10. Если готовых OHLC нет, M1 может строиться только из реально полученных тиков: первая точка не позже пятой секунды, последняя не раньше пятидесятой, разрывы не более десяти секунд, период уже завершён. Источник таких свечей отмечается в объяснении. Неполные интервалы не дорисовываются; готовая брокерская свеча имеет приоритет.

Каталог больше не считается устаревшим только потому, что прошло 60 секунд после его получения: он действует, пока свежие котировки идут из того же открытого канала. Его исходная дата не меняется. Закрытие канала отменяет доступность; новый канал должен передать собственный каталог. Изменённая выплата или закрытие пары учитываются сразу после получения. Для старого расширения без идентификатора канала прежний срок 60 секунд сохраняется.

При недостатке свечей приложение ждёт автозагрузку с видимым прогрессом, затем пишет причину отсутствия данных. В раскрытом списке есть имя последнего события истории, период, число строк и распознанных свечей либо причина отказа. Это обезличенная диагностика формата; распознано не означает принято после всех проверок времени/OHLC. Количество пар в каталоге не гарантирует подходящий вход. История, которая ещё не поступила, не возникает от повторного нажатия кнопки.

## Отметить вход и наблюдать с телефона

Сделку открываешь в Pocket Option самостоятельно. После этого в карточке сценария выбери фактический режим счёта и нажми **«Я открыл сделку»**. При желании укажи цену исполнения: иначе начальной точкой будет последняя полученная котировка с явной подписью, что это не подтверждённая цена исполнения. Отсчёт выбранного времени начинается с нажатия. Его нужно сопоставлять со временем закрытия у брокера.

Карточка сохраняется на сервере для твоего подписанного Telegram-пользователя и открывается на другом устройстве того же аккаунта. График показывает полученные цены после отметки входа, линию входа, оставшееся время и объяснение. Проверка Mini App идёт примерно раз в две секунды; фактическая задержка зависит от терминала, браузера, сети и туннеля. При отсутствии свежей котировки больше десяти секунд показано ожидание связи, пропущенные участки графика не дорисовываются. Возможны до трёх незавершённых отметок.

После окончания времени появятся **«Плюс / Минус / Возврат»**. Сверь результат у брокера и выбери его. Запись появится в «Моих сделках» в разделе результатов, указанных тобой; объяснение сохраняется. Эти отметки не изменяют баланс Pocket, полученный журнал брокера, его статистику или денежную цель. Повторный запрос не дублирует запись; результат после сохранения не переключается.

## Подключение с нуля

Установи Python 3.12 или новее с [python.org](https://www.python.org/downloads/windows/). Распакуй весь архив и запусти `START-WINDOWS.cmd`. Администратор не требуется: программа работает из личной папки `%LOCALAPPDATA%\TRED`, устанавливает зависимости с проверкой хешей и загружает официальный cloudflared 2026.10.1 с проверкой SHA-256.

Когда появится HTTPS-адрес, открой TRED из Telegram → «Кабинет → Подключить кабинет» и сохрани адрес. Получи одноразовый код (5 минут). В `chrome://extensions` / `opera://extensions` включи режим разработчика → «Загрузить распакованное расширение» → папка `connector`. В расширении TRED укажи тот же адрес и свежий код. В Pocket войди самостоятельно и обнови вкладку терминала. При запросе модуля подтверди ID из своего профиля и валюту, которую действительно видишь. Чужой Telegram ID вместо Pocket ID не используется.

Для второго устройства нужен тот же Telegram-аккаунт. На уже связанном устройстве дождись надписи «Подключение сохранено в Telegram и доступно на твоих устройствах», затем открой TRED на телефоне. CloudStorage хранит только проверенный HTTPS-маршрут и ID владельца; коды, ключи, баланс, Pocket ID, пароль и initData туда не записываются. Приватный API проверяет подпись Telegram; один числовой ID не даёт доступа. Срок действительности текущей Telegram-подписи — час; при истечении открой приложение заново.

## Если что-то не обновляется

- Оставь первое окно сервера открытым; новое окно при уже занятом порте не нужно.
- После перезапуска Quick Tunnel адрес может измениться. Старый адрес не переносит соединение на новый сервер. Если HTTPS выдаёт HTML вместо JSON, проверь текущий адрес и работу сервера.
- `DNS_LOOKUP_FAILED`, когда канал `CONNECTED`, означает, что Windows не находит адрес. Доступ пока не подтверждён: приложение проверит сервер со своей сети. На телефоне попробуй мобильный интернет. Подробности сохраняются в локальном `tunnel-diagnostics.json`.
- Для UTC+2 котировок в расширении есть явный профиль Pocket Option UTC+2 → UTC. Он применяется только к меткам котировок/свечей. Автоматическая подгонка ко времени прибытия отключена. Часовой пояс Windows не исправляет часы: в Windows используй «Синхронизировать сейчас» при ошибке времени.
- Баланс читается из явно распознанного видимого блока QT Demo USD / QT Real USD и поддерживаемых входящих событий. Несколько видимых счетов, неподдерживаемая валюта либо известное противоречие ID блокируют догадки. Новая сумма передаётся после стабилизации отображения; проверка открытого терминала — раз в 5 секунд. Фоновый браузер может замедлять таймеры.
- У симуляции отдельный баланс и дневные лимиты. Они не блокируют ручные ордера на сайте брокера. Перекрытия отключены; дневной сброс — 00:00 UTC.

## Проверка сборки

`python check_ai_scan_ui.py` прогоняет полный каталог 130 строк и автообход 16 подходящих пар: реальные скрипты запроса истории → подписанный API → клиент Responses с локальным тестовым провайдером → решение в Mini App одним нажатием. Это контрактная проверка, не вызов реального платного провайдера или сертификация нативного брокера. `python -m unittest -q` проверяет API, деньги, изоляцию пользователей, свежесть истории, направления вверх/вниз, фильтр выплат и сопровождение. `node check_connector.js`, `node check_connector_worker.js`, `node check_data_client.js` проверяют нормализацию и сохранение связи. `python check_market_feed_ui.py` прогоняет синтетический Fast-пакет через реальные observer/worker/API/интерфейс: 16 пар без истории, получение свечей, настоящий расчёт, каталог старше 60 секунд и закрытие канала. `python check_signal_ui.py` проверяет подписанный API и две независимые страницы приложения: отсутствие сигнала без истории, сценарий, вход, живые изменения цены, потерю связи и ручной результат. Браузерные проверки для разработки требуют Playwright и Chromium; для обычного запуска они не нужны. Это проверка функциональности, не бэктест доходности и не подтверждение нативного брокерского потока. Нативная загрузка распакованного MV3 в управляемом облачном Chromium ограничена политикой администратора; обход не выполняется.
