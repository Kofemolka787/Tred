# TRED 0.3.11 — бесплатный сервер на своём компьютере

Это версия для проверки подключения, учёта сделок и симуляции. Она **не открывает реальные сделки**, не входит в Pocket Option по паролю и не обещает проходимость. На компьютере владельца подтверждён приём каталога пар и котировок. Баланс и учёт сделок требуют отдельной проверки: форматы событий брокер может менять. Неизвестные форматы пропускаются, неизвестные результаты не становятся выигрышами.

## Запуск на Windows x64

1. Распакуй весь архив в отдельную папку. Не запускай файлы прямо из ZIP.
2. Установи Python 3.12+ с https://www.python.org/downloads/windows/ (если его ещё нет).
3. Открой папку `TredBackend` внутри распакованного архива и дважды нажми `START-WINDOWS.cmd`. Он скопирует проверенные файлы программы в `%LOCALAPPDATA%\TRED`, создаст там окружение Python, установит зависимости по зафиксированным контрольным суммам, загрузит официальный cloudflared 2026.10.1 с проверкой SHA-256, запустит API и проверит HTTPS-доступность. Регистрация, карта, BotFather-токен и пароль Pocket Option не нужны.
4. Когда появится `https://…trycloudflare.com`, открой TRED **из Telegram**, зайди в «Кабинет → Подключить кабинет» и вставь адрес. Если Windows сообщает об ошибке DNS и адресе для проверки с телефона, доступ пока не подтверждён: приложение сначала самостоятельно проверит HTTPS-сервер. Сервер проверит подпись Telegram. Одноразовый код будет показан только тебе на пять минут.
5. В Opera открой `opera://extensions`, включи режим разработчика, нажми «Загрузить распакованное расширение» и выбери папку `connector`. В Chrome аналогично: `chrome://extensions`.
6. Открой модуль TRED в панели расширений. Вставь адрес и одноразовый код. Войди в Pocket Option самостоятельно и **обнови его вкладку**. Пароль и SSID не нужно копировать.
7. Для другого устройства открой того же Telegram-пользователя и вставь тот же HTTPS-адрес. Личные данные доступны только по настоящей подписи Telegram этого пользователя. Друзья связывают свои кабинеты собственными кодами.

Компьютер, окно сервера и Pocket Option должны оставаться включены. После перезапуска бесплатный адрес меняется: повтори ввод адреса и привязку модуля. Туннель не предназначен для гарантированного круглосуточного сервиса, возможны ограничения сети и провайдера. Linux x64: `sh START-LINUX.sh`. Windows и работа туннеля на компьютере владельца требуют отдельной проверки; в облачной среде проверяется Python API на Linux.

## Что читается

Модуль наблюдает только входящие сообщения уже открытого терминала с `*.po.market`. Авторизация, cookies, пароль, сессия и сырые пакеты не пересылаются. Модуль передаёт только проверяемые поля баланса, валюты, ID, режима счёта, сделок, каталога и OHLC. Если режим, валюта или идентификатор не указаны явно, баланс не выдумывается. Пока поддерживается только явная валюта USD. Для другого формата нужна доработка адаптера по обезличенному примеру, не пароль пользователя.

Сканирование ограничено парами и таймфреймами, данные которых фактически пришли из браузера. Модуль не подписывается на все рынки сам. Для 30 минут нужны свежие истории M5 и M15 (минимум 80 закрытых свечей каждой) и свежая цена. Если терминал их не передаёт, приложение честно пропустит анализ. На OTC перехода без разрешения нет; закрытие обычного рынка проверяется по каталогу, а не по догадке о расписании.

Журнал — только наблюдавшиеся сделки: старые сделки автоматически не загружаются. Отдельные сделки без подтверждённого результата остаются открытыми. Симуляция хранится отдельно от сделок Pocket Option и от баланса брокера.

## Дневной стоп и дисциплина

Стартовая симуляция: виртуальные $100, ставка $1, дневной стоп $10, цель $20, нижний баланс $90, одна позиция, ноль перекрытий. Это изменяемые параметры симуляции, а не рекомендация по риску для реального счёта.

При новой позиции учитываются результат дня и все открытые ставки. После дневного стопа или дневной цели новые позиции заблокированы до следующего дня UTC. После первой позиции дня лимиты разрешено только ужесточать. Перезапуск не снимает блокировку и не запускает симуляцию автоматически. Неизвестная цена экспирации останавливает симуляцию, сохраняя ставку в резерве. Увеличение ставки после убытка не реализовано.

Стоп в TRED **не ограничивает ручную торговлю на сайте Pocket Option**. Настоящие деньги приложение не тратит. Цель $100 → $1000 отражает только наблюдённый чистый результат закрытых реальных сделок; пополнения и сделки демосчёта не прибавляются к заработку. Это план, не обещание дохода.

## Хранение и API

На Windows личная база хранится в `%LOCALAPPDATA%\TRED\data\ledger.sqlite3`, окружение Python — в `%LOCALAPPDATA%\TRED\python`, копия программы — в подпапке `app`. На Linux по умолчанию база находится в `private/ledger.sqlite3`. Не публикуй личную папку `%LOCALAPPDATA%\TRED`, папки `private`, `.venv`, `tools` и `server-url.txt`. В расширении хранится отдельный отзываемый ключ связи; в серверной базе — только его SHA-256. Код одноразовый и истекает за 5 минут; ключ — за 30 дней. «Отключить связь» отзывает ключ и приостанавливает симуляцию. История собственных сделок сохраняется.

API: `GET /healthz` открыт; `GET /api/state`, `POST /api/settings`, `/api/risk`, `/api/paper`, `/api/signal`, `/api/pair`, `/api/unlink` требуют `X-Telegram-Init-Data` с действительной подписью Telegram (до 1 часа). `/api/bridge/claim` обменивает одноразовый код, `/api/bridge/events` требует Bearer-ключ модуля. Пользователь не выбирается полем в теле запроса. Никаких `/order`, `/withdraw` или API реального исполнения нет.

Если ничего не обновляется: посмотри статус модуля, обнови Pocket, проверь USD / явный режим в событиях, доступность туннеля и подпись Telegram. Не отправляй пароли, SSID, HAR, cookies или полные логи сетевых сообщений. Неподдерживаемое событие — ограничение текущего адаптера, не повод выключать проверки.

## Исправление запуска Windows в 0.3.1

В раннем архиве CMD-файл был записан с переносами LF и русским UTF-8-текстом: на Windows он мог читать команды обрывками. В 0.3.1 файл использует ASCII без BOM и переносы CRLF; сборка дополнительно проверяет и нормализует его перед упаковкой. Есть запасной запуск через `python`, если `py` отсутствует. Скачай `tred-backend-v0.3.1.zip` и распакуй отдельно от предыдущей папки. Текущая проверка подтверждает байты скачиваемого файла; полный запуск cmd.exe на компьютере владельца ещё нужно повторить.

## Исправление отказа в доступе в 0.3.2

Если Windows запрещает создать `D:\TredBackend\.venv`, новая версия запускает программу из личной папки пользователя. В распакованную папку программа ничего не записывает: она читает файлы, проверяет их SHA-256 и создаёт рабочую копию в `%LOCALAPPDATA%\TRED`. Туда же сохраняются Python-зависимости, база, скачиваемый cloudflared и server-url.txt. Права администратора не нужны. Предыдущая база `private/ledger.sqlite3`, если есть, переносится через согласованную SQLite backup; уже перенесённая база не перезаписывается. Второй одновременный запуск блокируется. Проверка на Linux подтверждает установку и работу локального API с этим размещением; повторный запуск настоящего Windows остаётся за владельцем.

## Если локальный API работает, но HTTPS не подтверждён

С версии 0.3.3 туннель использует официальный режим HTTP/2. Он может помочь в сетях, где недоступен QUIC, который Quick Tunnel выбирал по умолчанию. Это не гарантирует доступность Cloudflare в конкретной сети. Проверка сертификатов остаётся включённой.

Скачай свежий `tred-backend-v0.3.11.zip`, распакуй в новую папку и открой `START-WINDOWS.cmd`. Установленный Python, зависимости и личная база сохраняются. Во время проверки окно показывает код результата. Если запуск остановился с `Press any key to continue`, Enter только закроет завершившееся окно.

В 0.3.4 случай `DNS_LOOKUP_FAILED; канал: CONNECTED` больше не закрывает уже подключённый туннель: ошибка может относиться только к DNS этого компьютера. Окно показывает адрес с пометкой «доступ пока НЕ подтверждён». Оставь окно открытым, открой Telegram на телефоне → TRED → «Кабинет → Подключить кабинет» и вставь адрес. Приложение проверит настоящий HTTPS health-ответ и действительную подпись пользователя, прежде чем сохранить подключение. Если телефон тоже не соединяется по Wi-Fi, попробуй мобильный интернет. Это проверка другой сети, а не гарантия работы Cloudflare.

Сервер продолжает повторять проверку DNS с ПК; когда она проходит, адрес сохраняется в `server-url.txt` и появляется обычное сообщение готовности. Старый адрес предыдущего запуска удаляется. Ошибки TLS, неожиданный ответ и отсутствие подключённого канала не переводятся в этот режим ожидания. VPN-расширение только в Chrome обычно не влияет на сетевые запросы Python; системный VPN/прокси может влиять. Менять настройки Windows или выключать защиту для этого обновления не требуется.

Для диагностики достаточно последних строк этого окна или файла `%LOCALAPPDATA%\TRED\data\tunnel-diagnostics.json`. Он содержит только этап, протокол, категорию состояния канала и код HTTPS; сессий, паролей и баланса в нём нет. `TIMEOUT` — ответ не получен вовремя, `DNS_LOOKUP_FAILED` — не удалось определить адрес сервера, `TLS_VERIFICATION_FAILED` — не прошла проверка сертификата, `HTTP_…` — HTTP-код ответа; суффикс `CF_…` уточняет код Cloudflare. По одному общему сообщению предыдущей версии причину установить нельзя. Не отключай проверку TLS или защиту компьютера.

## Ошибка времени и обновление связанного расширения

В комплекте 0.3.5 расширение имеет версию 0.3.1. Оно отделяет состояние связи от ошибок передачи. При сохранённом ключе форма повторного кода скрыта. Неудачный обмен истёкшего кода не удаляет предыдущую связь. Новый код требуется при явном отказе сервером в ключе или при намеренной смене подключения.

События баланса, каталога, котировок, свечей и сделок передаются отдельными пакетами. Неподдерживаемые, будущие и устаревшие временные метки отбрасываются до передачи; часы брокера не сдвигаются и не заменяются временем получения. В окне видно, какой тип данных и поле отклонены и насколько отличаются от часов браузера. Исторические свечи и открытия сделок разрешены; будущая экспирация открытой сделки не считается ошибкой. Серверные проверки сохранены. Часть принятых событий не означает, что баланс или все графики уже поддерживаются: строка «Сервер принял» показывает фактически принятые типы.

Если используется уже связанное расширение: скачай `tred-backend-v0.3.11.zip`, распакуй его **поверх прежней папки TredBackend**, из которой загружен модуль, с заменой файлов. Сохраняй тот же путь к папке `connector`. Полная замена файлов пакета сохраняет согласованность SHA256SUMS.json для следующих запусков. Текущий сервер уже работает из личной рабочей копии, его останавливать или переустанавливать не нужно. На странице `opera://extensions` / `chrome://extensions` нажми круглую стрелку перезагрузки на карточке TRED, затем обнови Pocket Option. Не удаляй расширение: при обновлении на том же пути Chrome/Opera сохраняет его отдельное хранилище с привязкой. Закрытие всплывающего окна не отключает модуль.

Автоматический часовой пояс регулирует отображение местного времени. Для сверки самих часов Windows используется «Синхронизировать сейчас» в настройках даты и времени. Если ошибка осталась, пришли только строку диагностики нового расширения: в ней нет баланса, ID, паролей, кода связи или сессии. Источником ошибки может быть формат брокерского события; синхронизация часов не считается доказанным решением.

## Каталог принят, но котировки опережают время на 7200 секунд

В пакете 0.3.7 модуль имеет версию **0.3.3**. Обнови весь пакет поверх той же папки TredBackend с заменой файлов, нажми круглую стрелку на карточке расширения и обнови вкладку с графиком Pocket Option. Окно сервера оставь открытым; новый код связи не нужен.

В окне TRED CONNECT нажми **«Использовать Pocket Option UTC+2»**. После этого время котировок и свечей будет переводиться из выбранного формата источника в UTC. Настройка сохраняется; «Вернуть формат UTC» отменяет этот выбор. Она не меняет часы Windows, баланс, каталог или время сделок. Проверки возраста котировок (не более 60 секунд), будущего времени (не более 5 секунд) и закрытости свечей сохраняются. Если вкладка использует старый обработчик, события отклоняются с просьбой обновить Pocket Option.

Это явный выбор формата **конкретного потока**, не подбор сдвига по времени получения. UTC остаётся вариантом по умолчанию; произвольные сдвиги не поддерживаются. Модуль сохраняет только исходную и UTC-метку последнего принятого события каждого типа для проверки пересчёта, без цены, баланса и ID. API получает прежний набор полей с UTC-временем, поэтому работающий сервер обновлять не требуется. Старое событие не заменяется текущим временем.

Основание для этого профиля: у владельца поток updateStream опережает часы на 7200 секунд; открытая неофициальная библиотека PocketOptionApi также описывает наблюдавшийся UTC+2 у потока и истории: [time_sync.py, строки 13–21](https://github.com/chema-creator/PocketOptionApi/blob/767c57a3282cd43901ad284f041b03cec581543b/pocketoptionapi/ws/objects/time_sync.py#L13-L21) и [перевод времени истории в stable_api.py](https://github.com/chema-creator/PocketOptionApi/blob/767c57a3282cd43901ad284f041b03cec581543b/pocketoptionapi/stable_api.py#L615-L627). Это не официальная спецификация брокера и не гарантия для всех его серверов. Другие форматы и неверные часы требуют отдельной диагностики. Формат времени сделок этим профилем не изменяется без подтверждения его схемы.

## Если код не принимается или обновилась только часть расширения

В 0.3.6 расширение имеет версию 0.3.2. Окно и фоновый обработчик сверяют версии. Когда новые файлы окна работают со старым обработчиком, форма кода скрыта и появляется «Перезапустить модуль». Эта кнопка вызывает обычный chrome.runtime.reload для этого расширения и сохраняет его хранилище. Затем открой модуль снова. Не удаляй его и не загружай ещё одну копию из другой папки.

Обновляй весь TredBackend из tred-backend-v0.3.11.zip поверх прежнего пути с заменой файлов, затем нажми круглую стрелку на карточке TRED в браузере. Текущий сервер останавливать не требуется. В мини-приложении выбери меню ⋯ → «Перезагрузить», чтобы загрузить новый интерфейс. Ресурсы имеют отдельный номер версии для обновления кэша.

Код теперь явно показывает адрес сервера, для которого выдан. При редактировании адреса прежний код сразу убирается, ошибки соединения не оставляют старый код на экране. Запросы кодов выполняются последовательно; запоздавший ответ предыдущего сервера не перезаписывает текущий код. Повторное открытие окна сохраняет ещё действующий код; кнопка «Получить новый код» явно заменяет его. Копируется только действительный код текущего соединения. После перезапуска сервера сначала проверь актуальный адрес в обоих местах. Коды по-прежнему одноразовые и действуют до пяти минут; проверка на сервере не ослаблена.

HTML-страница вместо JSON теперь выводится с HTTP-кодом и просьбой проверить текущий адрес. Ошибка такого ответа не стирает сохранённый ключ. Ответ без корректного ключа не считается успешной привязкой. Форма блокирует повторный щелчок, пока обмен не завершён. При отсутствии ключа старые ошибки передачи скрыты, а при нестарте фонового модуля показана кнопка его перезапуска.

## Котировки поступают, а баланс пустой

В 0.3.8 (модуль **0.3.4**) кабинет отдельно показывает соединение и наличие счёта. Если котировки поступают, пустой баланс больше не обозначается как «Нет связи». Вместо этого написано, что баланс и ID Pocket-счёта ещё не получены. Telegram ID на основной карточке — отдельный идентификатор, он не подставляется вместо Pocket ID.

Обнови весь TredBackend из архива 0.3.8 поверх прежней папки с заменой файлов, нажми круглую стрелку на карточке TRED в списке расширений, затем обнови график Pocket Option. Сервер оставь работающим. UTC+2 и текущая привязка сохраняются.

Открой TRED CONNECT. Если брокер передал ID, режим и баланс, но не указал валюту, появится блок с **Pocket ID** и кнопкой **«Мой счёт в USD — подтвердить»**. Нажимай её только если соответствующий счёт действительно в USD. Затем снова обнови график, чтобы получить новый баланс. Подтверждение действует только для указанного Pocket ID и режима (реальный/демо), сохраняется между запусками модуля и отменяется отдельной кнопкой. При новой привязке оно сбрасывается. Если сведения старше пяти минут, сначала обнови график. Явно указанную другую валюту заменить на USD нельзя. Другие валюты пока не поддерживаются.

Обработчик теперь объединяет явно полученные метаданные и обновления баланса в рамках одного WebSocket. Разные соединения, Pocket ID и режимы не делятся валютой или ID. Поддержан также входящий JSON-объект баланса без заголовка события; отправляемые браузером команды не читаются. Отсутствующие ID/режим не угадываются: окно показывает конкретную причину. Сырые пакеты и поля авторизации по-прежнему не передаются и не сохраняются. Локально сохраняются только ID/режим/состояние валюты для подтверждения; прошлый баланс ради повторной отправки не сохраняется. Серверный API и его проверки USD, времени, суммы и изоляции пользователей не изменены.

В облаке проверены синтетические варианты сообщений, HTTP-передача в настоящую временную базу и интерфейс браузера. Приём реального баланса на компьютере владельца проверяется после обновления; приём котировок сам по себе его не подтверждает.


## Баланс получен, но Pocket ID отсутствует

В 0.3.9 (модуль **0.3.5**) были добавлены варианты `id` и `accountId` в ответе `successauth`; обычное поле `id` в произвольном сообщении баланса не считается ID счёта. В той версии любое несовпадение этих полей блокировало баланс; эта проверка заменена в 0.3.10, см. следующий раздел. Основание для вариантов: [неофициальный обработчик PocketOptionApi](https://github.com/chema-creator/PocketOptionApi/blob/55a0a1311427c766e632c15621daa591233912c4/pocketoptionapi/ws/client.py#L466-L469). Это не официальная спецификация и не подтверждение формата конкретного аккаунта владельца.

Если терминал всё равно не передаёт ID, открой TRED CONNECT **прямо на вкладке Pocket Option с нужным графиком**. Появится форма «Подтверди Pocket ID» с режимом счёта, который явно пришёл от брокера. Вставь номер из собственного профиля Pocket Option, при необходимости подтверди USD и нажми «Подтвердить счёт». Число вводится в расширение, не в поле кода Telegram. Пароли, SSID и cookies не нужны. Отправка номера в чат сама по себе не меняет настройки установленного расширения.

Подтверждение привязано к вкладке, конкретному WebSocket и режиму. Новый вход, соединение или перезагрузка графика требуют подтверждения заново, если брокер по-прежнему не сообщает ID. Последний введённый номер подставляется только в форму; автоматически к новому графику он не применяется. Явный номер брокера имеет приоритет над ручным. Режим счёта должен явно поступить от брокера. В 0.3.9 ручное подтверждение было доступно только при отсутствующем ID; в 0.3.10 оно доступно также при неподдерживаемом или неоднозначном формате. Окно отмечает, что ID подтверждён пользователем.

Последний корректный баланс без ID ожидает подтверждения **не более 60 секунд, только в оперативной памяти**. После нажатия отправляется это же значение с **исходной временной меткой**, без подмены времени текущим. Если сообщение устарело или фоновый модуль перезапустился, обнови график и подтверди ID в течение минуты. Баланс не сохраняется в хранилище расширения для повторной отправки. Ключ текущего подключения и выбранный UTC+2 сохраняются при обычном обновлении модуля. Новая привязка и отключение очищают ручные подтверждения.

Для обновления распакуй весь архив 0.3.10 поверх прежнего TredBackend с заменой файлов, нажми круглую стрелку на карточке TRED и обнови график. Окно сервера оставь открытым; повторная привязка не требуется. Живой баланс владельца будет подтверждён только после строки «Сервер принял: … баланс» и проверки кабинета. Приём котировок уже подтверждён отдельно.


## Разные поля ID — пакет 0.3.10, модуль 0.3.6

Номер `uid` теперь имеет приоритет: поля `accountId` и `id` могут обозначать другие сущности и не обязаны совпадать с ним. Пустой, нулевой либо отсутствующий UID в очередном обновлении баланса не стирает UID, уже полученный в том же соединении. Изменившийся основной UID создаёт новый контекст счёта и очищает метаданные валюты. Без UID единственный согласованный положительный цифровой `accountId` (либо `id` только в `successauth`) поддерживается как прежний вариант формата. Иные форматы автоматически не преобразуются в номера.

Если ID остаётся неизвестным, текст «Баланс получен. Подтверди Pocket ID…» сопровождается только именами разрешённых полей и типами значений, например `uid — текст`. Значения непрочитанных ID, сырые сообщения и данные авторизации не выводятся и не передаются серверу. Для разделения неизвестных основных ID используется локальный отпечаток в памяти конкретного WebSocket; он также не пересылается. Изменившийся неизвестный UID требует нового подтверждения, а не наследует ручной номер.

Открой расширение **на нужной вкладке Pocket Option**, скопируй Pocket ID из своего профиля, проверь показанный демо/реальный режим и подтверди валюту, только если счёт в USD. Нажми «Подтвердить счёт» в течение минуты после обновления графика. Принятый баланс сохраняет исходную сумму и время. Сразу после подтверждения открой кабинет TRED; повторное обновление графика создаёт новый контекст и может снова потребовать подтверждения ID. Для другого формата валюты, отсутствующего режима, устаревшего или некорректного баланса форма не обходит проверки.

Для обновления замени файлы **в прежней папке TredBackend** всем содержимым нового архива, перезагрузи карточку расширения и проверь версию **0.3.6**. Затем один раз обнови график и открой TRED CONNECT. Работающий сервер оставь открытым. Повторный одноразовый код не нужен. Эта доработка проверена на изолированных событиях и настоящем локальном API; отображение баланса владельца требует отдельного подтверждения после установки. Пароль, почта и сессия для этого исправления не нужны.


## Автообновление без повторного ID — пакет 0.3.11, модуль 0.3.7

Баланс демосчёта владельца и приём изменений после ручного подтверждения ID подтверждены на его компьютере. В прежней версии подтверждение относилось к одному WebSocket, поэтому после пополнения или пересоздания соединения снова появлялась форма. В этой версии выбранный владельцем ID сохраняется как профиль браузера отдельно для каждого режима. При обновлении на том же пути переносится уже сохранённый профиль текущего счёта: удалять расширение, вводить новый код или подтверждать прежний ID заново не нужно.

Если брокер сообщает устойчивый непрочитанный UID, используется его односторонний SHA256-отпечаток с отдельным пространством имён; исходное значение и авторизация не покидают страницу. Отпечаток сохраняется только в закрытом хранилище расширения, не выводится в статусе и удаляется из события перед API. Тот же признак переживает новый WebSocket, повторную авторизацию, обновление страницы и перезапуск фонового модуля. Другой устойчивый признак не наследует ID. Для неоднозначных положительных цифровых полей авторизации также используется отпечаток их сочетания; произвольное поле сделки `id` сюда не относится.

Если устойчивого признака нет, источник не позволяет доказать автоматическое распознавание смены пользователя. Тогда используется именно настроенный владельцем профиль этого браузера и режима — это видно по пометке «Pocket ID сохранён тобой», а не считается ID, проверенным брокером. **Перед входом в другой Pocket-аккаунт нажми «Сменить Pocket ID»** либо отключи связь. Явный цифровой UID брокера имеет приоритет. Демо и реальный режимы, USD и другая явно указанная валюта не смешиваются. Смена ID в уже заполненном серверном кабинете по-прежнему требует явного отключения прежней связи; клиент не обходит серверную защиту.

Новые входящие изменения баланса отправляются сразу с обычной задержкой очереди до секунды. Пока терминал открыт, отдельная проверка доставки запускается каждые **15 секунд**, даже если окно расширения закрыто. После временной сетевой ошибки она повторяет только непереданный свежий баланс с **исходной суммой и временем**. При возрасте более 60 секунд повтор отменяется. Отказ ключа 401, смена профиля или отключение связи не обходятся повтором. Прошлый баланс не хранится для воспроизведения и не пересылается заново как будто получен сейчас. Таймер фоновой вкладки может ограничиваться браузером; это не гарантированный интервал брокерских событий.

Кабинет, пока открыт, уже получает состояние сервера каждые две секунды. Итог сделки отразится в балансе, когда терминал пришлёт поддерживаемое обновление баланса. Модуль не открывает сделки, не обновляет страницу автоматически и не посылает торговые или авторизационные команды. Вкладка Pocket Option, сервер и компьютер должны продолжать работать. Без нового брокерского события баланс не выдумывается. Поддержка полного журнала реальных сделок остаётся отдельной проверкой, приём демобаланса не подтверждает её.

Обновление: распакуй весь архив 0.3.11 **поверх прежнего TredBackend** с заменой файлов; на странице расширений перезагрузи карточку TRED до версии **0.3.7**, затем один раз обнови график Pocket Option для загрузки новых файлов. Работающий сервер оставь открытым. После этой установки изменения баланса выбранного счёта идут без ручного перезапуска и повторного подтверждения. Ключ связи, выбранный UTC+2, подтверждённый ID и USD переносятся при обновлении на том же пути.
