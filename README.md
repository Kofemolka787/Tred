# TRED Mini App

TRED v0.3.23 for @Tr1edBot_bot. Open https://kofemolka787.github.io/Tred/ from Telegram.

[Setup and update in Russian](backend-src/CONNECT-RU.md) · [Backend source](backend-src/) · [Download 0.3.23](https://kofemolka787.github.io/Tred/tred-backend-v0.3.23.zip)

Five independent setup families now cover Smart Money, EMA20/50 trend pullbacks, breakout/retests, range rebounds and false breakouts. Each has its own market-regime/context conditions; a range setup does not require trending SMC pivots. The model selects an exact symbol/direction/strategy tuple, with fresh revalidation of that same setup. EMA/Wilder ATR/RSI, Bollinger, MACD and Stochastic facts are computed from closed bars; indicators are confirmations, not independent promises of winning trades. The UI identifies the strategy, weakness and actual full-data coverage, and preserves them in the user-reported journal. Periods are explicitly seconds (300=M5, 900=M15). See [Russian strategy details](backend-src/STRATEGIES-RU.md). Synthetic recognition and signed mobile/API checks pass; no real profitability or model-weight training is claimed.

Read-only demo/real Pocket balances, Telegram-scoped connection discovery, and LunaRoute or direct OpenAI review of price structure/Smart Money evidence for 5/10/15-minute scenarios. Catalog and pair selection show all received instruments, including non-currency categories, without the former 24/100-row truncation. Only open instruments meeting payout/expiry filters are analyzed (prefer 92%, floor 85%).

The connector automatically requests quotes and history for matching catalog instruments through the already-open native socket. Only subfor/loadHistoryPeriod market-data requests are generated; no orders, login frames, credentials or chart-switch commands. Requests are paced, history concurrency is bounded, failures do not starve the rest of the catalog. The UI shows data coverage and waits for collection before AI review. Unknown/missing data is visible, never invented. Native broker protocol compatibility must be verified after installation.

Connector 0.3.13 fixes pending request release for unindexed Fast history replies and verified OHLC spacing when a response lacks its period. A fresh genuine tick completes a quote probe independently of response index metadata. Quote recovery shares the paced request budget with history; silent subscriptions and unanswered histories cannot consume all capacity. The limits remain one read-only request per 400ms and two pending replies, with at most one request per instrument. No timestamp rebasing, OHLC-close-as-live-price substitution, orders or chart switches. The server also reuses already verified aggregated history instead of redundantly downloading 160 native bars. Update the same extension card, refresh Pocket once and restart the updated server once; saved key, model and account profiles persist. A random tunnel URL can change on restart, so update that route if necessary. A cold 41-pair local fixture receives both history periods for all 41 by 100 simulated seconds and keeps 12–13 current prices simultaneously; it does not establish all-pair simultaneous live coverage or real broker latency.

The model response contract is now explicit in the prompt as well as the API schema. The model selects short evidence references rather than retyping epoch timestamps; references are mapped to immutable source facts and validated before any entry. Only data-ready pairs get reference IDs, all catalog rows remain, and batch byte limits include the reference catalog. One complete JSON fence is tolerated; prose, partial output, duplicate JSON fields, invented/cross-pair references and repeated evidence do not become entries. Safe UI diagnostics distinguish missing/refused/completed-but-invalid model responses from transport failures; raw provider text is not exposed and no paid format-repair retry is sent. These cases pass local fixtures, including 5/10/15-minute periods and mobile UI. Actual native model output still requires owner verification.

The real Responses API client uses bounded incremental SSE for LunaRoute and accepts only a completed, validated result without waiting for connection EOF. Missing/stale pairs retain explicit inventory summaries instead of repeated full OHLC; ready pairs retain causal facts and closed samples. In the mixed 39-pair fixture one full pair reduced snapshot bytes from 329798 to 27148 with all rows retained and one model call. This is a fixture measurement, not a service latency guarantee. DNS, TLS, timeout and connection failures have distinct sanitized messages, and paid requests are never automatically retried. The client sends only market evidence, closed OHLC samples and computed causal SMC/structure facts, with store:false and structured output validation. Every received eligible pair enters the review, with bounded batches and winner comparison for large catalogs. The selected model chooses or declines an entry, within locally verified directions/entry conditions; timestamps and prices are checked again after the response. No forced signals, measured win probability or profitability claims. OTC patterns do not establish exchange order flow or actual liquidity. Longer expiry does not guarantee accuracy.

SETUP-LUNAROUTE.cmd fetches the authenticated LunaRoute model catalog and verifies a short paid structured Responses request before saving the key. SETUP-AI.cmd remains available for direct OpenAI. The setup accepts the owner's API key locally with visible terminal input as requested by the owner and stores it only in the private user directory, scoped to the existing paired Telegram owner. ChatGPT subscriptions do not cover API billing. The key is visible in the local setup console while entered, and is absent from the Mini App, Telegram storage, archive and state API. Blank key input is re-prompted; HTTP401/403/404/429 setup errors are distinguished without echoing provider payloads. Other users cannot spend that owner's key. Real provider errors are visible; analysis never silently falls back to a rule-only signal. LunaRoute model selection uses the actual available catalog, supports provider/model identifiers, and preserves prior settings on failure. The official gateway is https://gw.lunaroute.com/v1, authenticated with a Bearer lr_ key; no Node.js/CLI installation is required. Saved provider settings take priority over unrelated provider environment keys. In-flight results are discarded when provider settings change.

After independently entering a trade, the same signed user can follow received quotes from another device and report win/loss/draw after expiry. The app shows entry window, chosen duration, estimated close time and AI explanation. Manual outcomes stay separate from broker balances/statistics. Existing balance delivery and cross-device cabinet were owner-confirmed; the new native scanner and actual owner provider calls still require installation and validation.

Functional checks cover the real API client against a local fixture provider, native-shaped synthetic market responses, complete connector/backend/browser flow, catalog130/eligible16 coverage, preserved balance, stale review rejection and user isolation. They are not a profitability backtest or a real broker/OpenAI certification. No bot tokens, broker sessions, passwords, private state or owner IDs are published. See the Russian guide for the single replacement ZIP, local AI setup, remaining limits and exact checks.
